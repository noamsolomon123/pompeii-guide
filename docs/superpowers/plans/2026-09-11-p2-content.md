# P2 Content Pipeline Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn `content/research/<id>.md` (sourced English research, 26 stops) into finished Hebrew guide scripts per stop in `content/stops/<id>.json`, compile them into `www/stops.json`, then (when keys exist) proofread via an external Hebrew pass and render MP3s.

**Architecture:** `content/stops/*.json` is the single source of truth for stop content; `www/stops.json` is generated by `scripts/build-stops.mjs` (validated, ordered). Scripts are written by an LLM writer per stop-group with a strict style guide, then reviewed by a separate Hebrew reviewer agent. Proofreading (Gemini/OpenRouter) and TTS rendering are separate, key-gated steps.

**Tech Stack:** Node 24 scripts, `node --test` for the builder/validator.

## Stop JSON schema (`content/stops/<id>.json`)

```json
{
  "id": "vettii", "order": 10, "optional": false,
  "name_he": "בית הווטי", "name_en": "House of the Vettii", "regio": "VI",
  "gps": [40.75150, 14.48460], "gps_quality": "exact|approx",
  "hours": "09:00-17:00", "status": "verify_winter",
  "cues": ["…5–8 visual identifiers in Hebrew…"],
  "open30": "…70–95 Hebrew words, spoken, ~30 s…",
  "deep": "…230–300 Hebrew words, spoken, ~2 min…",
  "look_for": "…1–2 sentences: the detail most visitors miss + where to stand…",
  "next_nav": "הבא במסלול: <name_he>, כ-<N> דקות הליכה <כיוון>. <one orientation hint>.",
  "faq": ["שאלה? תשובה קצרה.", "…4 items…"],
  "anecdotes": ["…2–3 short sourced true stories, Hebrew…"],
  "sources": ["https://…"],
  "notes": "verification flags copied from research (e.g. hours to re-check, disputed facts)"
}
```

## Hebrew style guide (binding for every writer)

- **Spoken Hebrew, guide's voice, present tense, addressing a couple ("אתם", "תראו", "שימו לב").** Not encyclopedia. Short sentences. No bullet points inside text. Numbers written as words when ≤ 20 (spoken by TTS), years as digits ("בשנת 79 לספירה").
- **Every foreign name:** Hebrew transliteration first, Latin/Italian original once in parentheses on first use in `open30` only: "בית הווטי (House of the Vettii)". After that Hebrew only. Use the `## Hebrew naming` section of the research file.
- **No invented facts.** Only what the research file says. Disputed → say "יש חוקרים שסבורים…". Numbers exact.
- **Structure of `open30`:** (1) where we are + one hook sentence, (2) what this place was and who was here, (3) one striking fact, (4) what to look at right now. End with an implicit invitation ("רוצים שאעמיק? תגידו לי.").
- **Structure of `deep`:** story arc: before → the people → art/technology → AD 62 earthquake / AD 79 eruption / excavation → a debate or recent discovery → closing image. No repetition of `open30` sentences.
- **`next_nav`:** direction from this stop to the next in route order (see table), walking minutes estimated at 80 m/min from the GPS in the research files; if GPS is approx say "בערך". One orientation hint (a street name in Hebrew transliteration, a landmark).
- **Avoid:** English words, Anglicisms, passive voice piles, "מדהים/מרהיב" more than once per stop, exclamation marks.
- Punctuation that TTS reads well: commas and periods; no dashes, no parentheses except the single name gloss.

### Task 2: Write scripts, group B (tragic-poet, faun, vettii, thermopolium, villa-mysteries)

### Task 4: Write scripts, group D (triangular-forum, large-theatre, quadriporticus, octavius-quartio, venus-shell, fugitives, amphitheatre, palaestra)

For each stop in the group:
- [ ] Read `content/research/<id>.md` fully and the seed entry in `www/stops.json`.
- [ ] Write `content/stops/<id>.json` per schema + style guide. `gps` from the research Identity section (decimal; `gps_quality` exact only if the source is a surveyed point/OSM node, else approx). `hours` = winter schedule from research (9:00–17:00 unless research says otherwise), `status` = `verify_winter`. `notes` = the research file's thin-source flags, one line each.
- [ ] Self-check: word counts (`open30` 70–95, `deep` 230–300), no English inside Hebrew fields except the single gloss, JSON valid (`node -e "JSON.parse(require('fs').readFileSync(p,'utf8'))"`), UTF-8 no BOM.
- [ ] Commit per group: `content: Hebrew scripts group <X>` (explicit `git add content/stops/<ids>.json`).

### Task 5: Hebrew review pass (separate agent per group)
- [ ] Reviewer reads each JSON + research file; checks: factual fidelity to research (every claim traceable), style guide compliance, naturalness (would an Israeli guide say this?), TTS-readability, word counts, `next_nav` direction sanity vs GPS. Fixes inline, commits `content: review fixes group <X>`, reports a list of changes.

### Task 6: Builder + validator (tested)
**Files:** `scripts/build-stops.mjs`, `scripts/test/build-stops.test.js`, `package.json` script `build:stops`.
- [ ] `build-stops.mjs`: read all `content/stops/*.json`, validate (schema keys present, ids unique, orders unique among non-optionals and cover 1..24, `gps` null or `[lat,lng]` in Pompeii bbox lat 40.745–40.757 / lng 14.478–14.500, word counts within range, `next_nav` non-empty, no `�`), sort by `order`, write `www/stops.json`. Exit 1 with a readable list on any violation.
- [ ] Test with a temp dir fixture: valid set builds; missing key / duplicate order / out-of-bbox gps each fail with the field named.
- [ ] Run it; commit `content: build www/stops.json from content/stops` (both the script and the regenerated `www/stops.json`).

### Task 7 (key-gated): proofread
**Files:** `scripts/proofread.mjs`
- [ ] For each Hebrew field, POST to OpenRouter chat (`google/gemini-2.5-pro` or the bake-off winner) with a strict system prompt: "אתה עורך לשון עברי. תקן שגיאות דקדוק, תחביר וניסוח לא טבעי. שמור על המשמעות, על אורך דומה ועל הטון הדיבורי. החזר רק את הטקסט המתוקן." Write results to `content/proofread/<id>.json` and a unified diff to `content/proofread/<id>.diff`. Human reviews diffs, then `scripts/proofread.mjs --accept <id>` copies accepted fields back into `content/stops/<id>.json`. Rebuild.

### Task 8 (key-gated): TTS render
**Files:** `scripts/tts.mjs`
- [ ] For each stop and layer in `open30|deep|next_nav`: POST OpenRouter `/audio/speech` (model/voice from `docs/superpowers/specs/bakeoff-result.md`) → `www/audio/<id>-<layer>.mp3`. Skip if file exists and is newer than the JSON. Also render `www/audio/_no-network.mp3` ("אין רשת כרגע, אענה כשנחזור") and `www/audio/_depth-offer.mp3` ("רוצים שאעמיק?"). Report total seconds + cost from response usage. Add `www/audio/*.mp3` to git (they ship in the APK; ~26×3×~0.5 MB ≈ 40 MB — acceptable; if over 100 MB switch to Git LFS).
